# villa.photos en portfolio dev

Para portfolio dev, **sí la añadiría**, pero la presentaría con cuidado.

Esta web no es solo "hice una página bonita de fotos"; puede contar bastante bien varias capacidades técnicas:

- Angular moderno.
- Pipeline propio de optimización de imágenes con Sharp.
- S3 + CloudFront.
- Generación de manifest `photos.json`.
- Lazy loading, blurhash/placeholders, preload selectivo.
- Rutas limpias.
- Sitemap dinámico.
- Analytics de interacción.
- UI responsive y cuidada.
- Automatización de build/deploy.

Eso como proyecto de portfolio dev tiene buen valor porque mezcla frontend, performance, tooling, cloud y producto real.

Yo la pondría como proyecto tipo:

```txt
villa.photos
Portfolio fotográfico optimizado con Angular, Sharp, S3 y CloudFront.
```

Y en descripción:

```txt
Desarrollé una galería fotográfica estática con pipeline propio de generación de assets: procesamiento de imágenes con Sharp, publicación en S3/CloudFront, manifest JSON, lazy loading, blurhash placeholders, rutas limpias, sitemap y eventos GA4 para medir interacción.
```

Puntos técnicos destacables:

```txt
- Image pipeline con Sharp y generación automática de WebP.
- Manifest remoto servido desde CloudFront.
- Lazy loading progresivo con IntersectionObserver.
- Placeholders visuales mediante BlurHash.
- Rutas directas por fotografía y categorías.
- Sitemap generado desde el manifest de fotos.
- Tracking de eventos GA4 para apertura, navegación y contactos.
```

No lo vendería como "gran aplicación compleja", sino como **producto pequeño pero bien acabado**. Eso suele funcionar muy bien en portfolio dev: demuestra criterio, detalle y capacidad de llevar algo a producción.

Si tu portfolio `yoelvilla.dev` tiene proyectos, yo la añadiría como caso real, con enlace live y quizá enlace a GitHub si el repo es público.
